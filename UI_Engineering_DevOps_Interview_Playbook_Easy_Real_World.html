Q1. Your React app has a good Lighthouse score in lab tests, but real users in India report slow first load. How do you investigate and fix this?
Real-world scenario
In a production UI application, lab: LCP ~1.8s on US broadband. Real users: LCP p75 ~4.2s on mid-tier Android. App served via global CDN.. The practical goal is to fix the user impact without guessing, while keeping the change measurable and reversible.
What the interviewer really wants to hear

Difference between synthetic and real user monitoring; prioritizing fixes by user impact. They want to see a clear order: understand the symptom, find evidence, fix the root cause, and verify the result.

Easy explanation
A lab test is like testing a car on an empty track. Real User Monitoring measures the same car in actual traffic, on real phones and networks.
Short interview answer

Start with RUM data, not Lighthouse. Then I would verify the result with production-relevant evidence and keep a safe rollback path.

Step-by-step production answer
  1. Start with RUM data, not Lighthouse.
  2. Segment Web Vitals by country, device class, network type, and browser.
  3. Check whether users in India hit the nearest CDN POP and whether the regional cache-hit ratio is low.
  4. Correlate LCP with connection setup and image download time.
  5. If LCP is image-dominant, use AVIF/WebP variants, responsive srcset, explicit dimensions, and fetchpriority=high for the hero.
  6. If JavaScript parse time is high, add route-level splitting, remove heavy polyfills, tree-shake UI libraries, and defer non-critical third-party scripts.
  7. Hashed JS/CSS should be immutable, while index.html should be no-cache.
  8. Re-measure p75 LCP and INP after each change.
Common mistake to avoid

Optimizing only a Lighthouse score and not checking real-user p75 data after the change.
