1. Frontend Optimization

Q1. Your React app has a good Lighthouse score in lab tests, but real users in India report slow first load. How do you investigate and fix this?
Scenario

Lab: LCP ~1.8s on US broadband. Real users: LCP p75 ~4.2s on mid-tier Android. App served via global CDN.

What the interviewer is testing

Difference between synthetic and real user monitoring; prioritizing fixes by user impact.

Strong in-depth answer

Start with RUM data, not Lighthouse. Segment Web Vitals by country, device class, network type, and browser. Check whether users in India hit the nearest CDN POP and whether the regional cache-hit ratio is low. Correlate LCP with connection setup and image download time. If LCP is image-dominant, use AVIF/WebP variants, responsive srcset, explicit dimensions, and fetchpriority=high for the hero. If JavaScript parse time is high, add route-level splitting, remove heavy polyfills, tree-shake UI libraries, and defer non-critical third-party scripts. Hashed JS/CSS should be immutable, while index.html should be no-cache. Re-measure p75 LCP and INP after each change.

Q2. A team asks to preload every JavaScript chunk to make everything fast. Should you do it?
Scenario

SPA with 18 chunks; team proposes preload tags for all chunks in head.

What the interviewer is testing

Browser prioritization and network contention.

Strong in-depth answer

No. Preloading everything promotes non-critical resources and makes them compete with the LCP image, critical CSS, and initial-route JavaScript. Preload only first-render dependencies such as the entry chunk, route-critical chunk, above-the-fold font, and LCP media. Use prefetch for likely next-route chunks. Validate through the DevTools priority column and compare LCP and TBT.

Q3. After adding a design system, bundle size increased from 300KB to 1.2MB gzipped. How do you reduce it without rewriting the app?
Scenario

Large component imports; startup CPU cost increased.

What the interviewer is testing

Bundle analysis and practical remediation.

Strong in-depth answer

Run a bundle analyzer and inspect parsed size, not only gzip. Replace barrel imports with supported path imports, use the ESM build, enable sideEffects-aware tree shaking, remove duplicate dependency versions, and lazy-load rare components such as chart editors, date pickers, and rich-text tools. Import icons individually and load only required locales. Add a CI bundle budget. Transfer reduction is only half the goal because parse and execution cost on low-end devices can dominate.

Q4. Your app has random INP spikes during typing in a search box. How do you debug and fix it?
Scenario

Users report input lag after large result sets load; INP p95 is unstable.

What the interviewer is testing

Main-thread scheduling and event-loop understanding.

Strong in-depth answer

Profile long tasks around input events. Determine whether synchronous filtering, expensive render trees, forced layout, or third-party work causes the delay. Capture each keystroke immediately and move heavy work to requestIdleCallback, a Web Worker, or incremental scheduling. Debounce network calls, virtualize results, memoize rows, and avoid layout reads after DOM writes. In React, isolate the controlled input from the large parent tree. Verify the INP distribution, not only its average.

Q5. Your CDN hit ratio is 45 percent for static assets and origin cost is increasing. What is wrong?
Scenario

Static assets use hashed filenames, but origin fetches remain high.

What the interviewer is testing

Cache-key design and cache-control strategy.

Strong in-depth answer

Check cache-key explosion. Query strings, cookies, and unnecessary headers can create unique keys. Static assets generally need a path-only key. Apply Cache-Control: max-age=31536000, immutable to hashed assets and ensure reverse proxies do not add no-cache. Check compression variants and frequent deploy churn. Keep index.html short-lived while hashed assets remain long-lived.

2. Web Security

Q6. A pentest reports reflected XSS on your search page. What is your immediate and long-term fix plan?
Scenario

A query parameter is rendered into the DOM for highlighting; the proof of concept executes alert().

What the interviewer is testing

Incident response and defense in depth.

Strong in-depth answer

Immediately encode output so user input is text, not HTML, and remove unsafe rendering paths. If highlighting needs markup, sanitize with a strict allowlist. Tighten CSP with nonce-based scripts, add malicious-payload regression tests, audit innerHTML, dangerouslySetInnerHTML and template-injection sinks, add security linting, and centralize safe component utilities. XSS is usually a process failure, not merely a one-line defect.

Q7. Why is storing JWT in localStorage risky, and what would you use instead?
Scenario

Current authentication stores its access token in localStorage.

What the interviewer is testing

Threat modeling and browser security boundaries.

Strong in-depth answer

localStorage is readable by JavaScript, so XSS can exfiltrate and replay a token. Prefer HttpOnly, Secure, SameSite cookies for session tokens, paired with SameSite policy, CSRF tokens for unsafe methods, and Origin checks. Keep access tokens short-lived and rotate refresh tokens server-side. Cookies reduce token read theft but do not eliminate XSS impact, so CSP and output encoding remain necessary.

Q8. Your security team wants strict CSP, but product uses third-party analytics and tag manager. How do you implement CSP without breaking tracking?
Scenario

Multiple external scripts and existing inline scripts.

What the interviewer is testing

Practical CSP rollout.

Strong in-depth answer

Begin with Report-Only and collect violations. Replace unsafe inline scripts with per-response nonce-based script tags, move inline event handlers to JavaScript listeners, explicitly allow only required vendor domains, and use Subresource Integrity where possible. Remove unknown dependencies, then enforce after violation volume is understood. CSP rollout also requires vendor governance and stakeholder alignment.

Q9. API requests fail in the browser but work in Postman. The CORS issue appears only in production. How do you fix it?
Scenario

Browser presents a preflight failure; Postman succeeds.

What the interviewer is testing

Correct understanding of CORS scope.

Strong in-depth answer

CORS is browser-enforced, so Postman success does not validate browser policy. Inspect OPTIONS. With credentials, Access-Control-Allow-Origin must exactly match the requesting origin and cannot be wildcard. Permit the actual methods and headers, add Vary: Origin for dynamic origin handling, and ensure CDN or proxy layers preserve CORS headers on error responses.

Q10. You must consume a third-party CDN script for business-critical chat. How do you reduce supply-chain risk?
Scenario

External script required; security is concerned about CDN compromise.

What the interviewer is testing

Supply-chain controls.

Strong in-depth answer

Use Subresource Integrity and an exact version URL, restrict CSP script-src, and avoid floating latest. Monitor unexpected outbound behavior, isolate the chat in an iframe on a separate origin where feasible, and keep a feature-flag kill switch for rapid disablement.

3. Docker

Q11. Why should a frontend app use multi-stage Docker builds?
Scenario

Current image is a 900MB Node image serving static files.

What the interviewer is testing

Runtime minimization and attack-surface reduction.

Strong in-depth answer

Use Node only in the build stage, then copy dist into a minimal Nginx or Caddy runtime. This reduces registry transfer, cold-start cost, and CVE surface and excludes development tooling. Production serves immutable static output rather than a development server.

Q12. Docker builds are slow in CI. What optimizations do you apply?
Scenario

Build time increased from 4 to 14 minutes.

What the interviewer is testing

Layer-cache strategy.

Strong in-depth answer

Copy lockfiles first, install dependencies, then copy source. Use BuildKit and remote cache, avoid broad COPY early, keep .dockerignore strict, separate stable from frequently changing dependencies, use targeted workspace installation in monorepos, and warm from the last successful image. Measure cache-hit and per-layer timing.

Q13. Why is running an Nginx container as root risky, and how do you run non-root safely?
Scenario

Security scan flags the root process.

What the interviewer is testing

Container hardening.

Strong in-depth answer

Use a non-root UID, read-only root filesystem, and drop unnecessary capabilities. Bind internally to a high port such as 8080, with Service or Ingress exposing 80/443. Provide explicit writable mounts for required temp, cache, or log paths. Enforce runAsNonRoot through Kubernetes securityContext.

Q14. Your Docker plus Nginx SPA returns 404 when refreshing /orders/123. Why?
Scenario

Client-side navigation works, but refresh fails.

What the interviewer is testing

SPA server fallback.

Strong in-depth answer

A refresh asks the server for /orders/123 as a real path. Configure try_files $uri $uri/ /index.html so application routes fall back to the shell, while keeping static-asset paths strict. If a CDN fronts the origin, verify its error mapping as well.

Q15. How do you prevent secret leakage in Docker builds?
Scenario

The team passes API tokens as ARG and commits the Dockerfile.

What the interviewer is testing

Build-time secret handling.

Strong in-depth answer

Do not embed secrets through ARG or ENV because image history and layers can expose them. Use BuildKit secret mounts, avoid echoing values, exclude .env files with .dockerignore, and obtain runtime secrets from an orchestrator or secret manager. Inspect image history and scanning results to verify absence.

4. Kubernetes

Q16. Explain readiness probe versus liveness probe with a real outage example.
Scenario

A new release caused intermittent 502s during rollout.

What the interviewer is testing

Probe semantics and rollout safety.

Strong in-depth answer

Readiness controls traffic eligibility; the pod stays running but is removed from Service endpoints when readiness fails. Liveness controls restart behavior. If readiness returns 200 before assets are ready, the load balancer can route traffic prematurely. Make readiness represent real serving state, add a startup probe for slow boot, and tune delay, timeout, and failure thresholds.

Q17. Your frontend pods are OOMKilled during traffic spikes. How do you solve it?
Scenario

Pods restart every few minutes and memory rises with traffic.

What the interviewer is testing

Resource management and autoscaling.

Strong in-depth answer

Inspect memory profiles, events, sidecars, requests, and limits. Set realistic requests for scheduling and limits for safety. Scale before saturation through HPA using appropriate metrics. Review Nginx workers, caching, logging, and sidecar pressure. Validate p95 memory and restart counts after changes.

Q18. Why use a PodDisruptionBudget for frontend apps?
Scenario

A node upgrade drained multiple pods and availability dipped.

What the interviewer is testing

Availability during voluntary disruptions.

Strong in-depth answer

A PDB constrains voluntary eviction so enough replicas remain available during maintenance or autoscaler scale-down. With three replicas and minAvailable two, Kubernetes preserves at least two when honoring the budget. Combine it with topology spreading for zone resilience.

Q19. A cluster has many namespaces. How do you isolate dev and production securely?
Scenario

Dev and production share an EKS cluster.

What the interviewer is testing

Multi-tenant governance.

Strong in-depth answer

Use namespace separation with scoped RBAC, NetworkPolicies, quotas, namespace-specific secrets, and IAM mapping. Admission policies can enforce security contexts and trusted image sources. CI identities for dev must not deploy to production. Strongly regulated environments may justify separate clusters.

Q20. You see high latency at ingress although pods are healthy. What do you inspect?
Scenario

ALB p95 latency increased while pod CPU remains normal.

What the interviewer is testing

End-to-end request-path analysis.

Strong in-depth answer

Trace CloudFront edge time, ALB target-response time, pod latency, and downstream calls. Inspect keepalive, TLS, cross-zone traffic, target health thresholds, and slow start. Confirm static assets are using the intended CDN policy. Correlate logs and metrics rather than assuming the pod is the bottleneck.

5. AWS CI/CD

Q21. Explain exactly how CodePipeline passes data from Build to Deploy.
Scenario

Build creates an image-tag file needed by Deploy.

What the interviewer is testing

Artifact-flow literacy.

Strong in-depth answer

CodeBuild writes files declared in buildspec artifacts. They are uploaded as an artifact to the pipeline S3 bucket. Deploy declares that artifact as input, receives it in its workspace, reads image-tag.txt, and passes it to Helm. The exact tested image is promoted rather than rebuilt.

Q22. Why use immutable image tags such as Git SHA instead of latest in production?
Scenario

The team deploys latest and cannot reproduce a rollback target.

What the interviewer is testing

Release traceability and determinism.

Strong in-depth answer

latest is mutable and ambiguous. Git SHA or digest references tie runtime to source and make deployment and rollback reproducible. Record image digest and commit metadata. latest may help cache workflows but should not identify a production release.

Q23. CodeBuild can push to ECR but Helm deploy to EKS is unauthorized. Why?
Scenario

ECR permissions are correct, but kubectl is denied.

What the interviewer is testing

AWS IAM authentication versus Kubernetes RBAC.

Strong in-depth answer

ECR and EKS authorization are separate. eks:DescribeCluster does not grant Kubernetes actions. Use an EKS Access Entry to grant the CodeBuild role cluster access; this is the AWS-recommended alternative to aws-auth ConfigMap mappings. Then bind a least-privilege Role or ClusterRole, then validate with kubectl auth can-i. Avoid system:masters and scope deploy identities by namespace.

Q24. The pipeline fails intermittently on Monday mornings because of build queue time. How do you stabilize it?
Scenario

Build starts are delayed during peak commits.

What the interviewer is testing

CI capacity planning and reliability.

Strong in-depth answer

Inspect concurrent build quotas and compute capacity. Separate fast-fail checks from heavy jobs, prioritize critical branches, consider reserved capacity, cache dependencies, shard tests, and retry transient network failures only. Publish and alert on queue latency.

Q25. CloudFront serves old index.html after deploy even though invalidation runs. What causes it?
Scenario

Assets update, but the shell remains stale for some users.

What the interviewer is testing

CDN versus browser and service-worker caching.

Strong in-depth answer

Check browser cache, intermediary cache, invalidation path, and service worker. index.html should be no-cache or no-store, and both / and /index.html may require matching treatment. Inspect the affected browser response headers to identify the actual cache source.

6. Helm and Release Management

Q26. Why does helm upgrade sometimes not restart pods after a configuration change?
Scenario

ConfigMap updated; pods still use old config.

What the interviewer is testing

Declarative reconciliation.

Strong in-depth answer

A ConfigMap change does not restart pods if the Deployment pod template is unchanged. Add a checksum annotation derived from ConfigMap content so the pod template changes and a rollout starts. A mounted file refresh also does not guarantee the application rereads it.

Q27. How do you design values files to avoid configuration drift across environments?
Scenario

Staging and production values diverged unpredictably.

What the interviewer is testing

Configuration architecture discipline.

Strong in-depth answer

Keep chart defaults minimal and environment overlays limited to true deltas. Validate types and required keys with values.schema.json. Avoid full copied values files. Render and diff each environment in CI, and track chart version separately from app version.

Q28. A Helm release failed midway. What does --atomic actually do?
Scenario

New pods failed readiness and the team expects automatic recovery.

What the interviewer is testing

Helm failure and rollback behavior.

Strong in-depth answer

With --atomic, Helm automatically enables --wait. For an upgrade that fails or times out, Helm rolls back to the last successful revision; for a first-time install, it uninstalls the failed release. Rollback or uninstall can also fail if the cluster is unhealthy. Reliable probes, practical timeouts, and release observability are still required.

7. End-to-End Incidents

Q29. Deployment succeeded but users see a blank production screen. What is your first-principles triage plan?
Scenario

Pipeline green, index.html returns 200, and a JS chunk returns 404.

What the interviewer is testing

Cross-layer troubleshooting.

Strong in-depth answer

Trace the missing chunk. Determine whether new HTML references an asset that was not uploaded or old HTML references a deleted asset. Verify deployment order, running image tag or S3 objects, CDN cache headers, invalidation, and service-worker state. Restore service with a known-good release, then enforce an atomic asset-first and shell-last release pattern.

Q30. All API calls suddenly return 401 after a UI-only release. What likely went wrong?
Scenario

Login appears successful, but protected API calls fail; backend is unchanged.

What the interviewer is testing

Authentication integration reasoning.

Strong in-depth answer

Inspect browser request headers and cookies. Compare the new build's credentials mode, cookie domain and SameSite assumptions, API-origin environment variable, CORS handling of Authorization, and runtime configuration. Add a post-deploy canary that authenticates and calls a protected endpoint before promotion.

Q31. How would you design a safe progressive rollout for a risky frontend change?
Scenario

A checkout redesign affects a revenue-critical flow.

What the interviewer is testing

Deployment-strategy maturity.

Strong in-depth answer

Place the change behind a feature flag, enable it for internal users, then gradually expose cohorts by region or device. Watch conversion, errors, INP, and payment failures. Keep two rollback layers: disable the flag immediately and roll back the release if needed. Add synthetic checkout canaries and guardrails that disable exposure when thresholds breach.

Q32. You must reduce monthly infrastructure cost by 30 percent without hurting UX. Where do you optimize first?
Scenario

AWS transfer, compute, and CI costs are rising.

What the interviewer is testing

Cost-performance tradeoffs.

Strong in-depth answer

Rank cost drivers. Improve CloudFront hit ratio, reduce asset bytes and egress, right-size Kubernetes requests and limits, tune HPA baseline replicas, filter redundant CI builds, and cache dependencies. Target expensive end-to-end tests by change type. Protect SLOs by tracking p75 Web Vitals and error budgets during optimization.

8. Quick Whiteboard Prompts

Q33. Draw the complete authentication chain from Git push to pod secret read.
Scenario

Whiteboard identity-flow exercise.

What the interviewer is testing

Identity boundaries across CI, AWS, EKS, nodes, and pods.

Strong in-depth answer

Include GitHub to CodePipeline through AWS CodeConnections (formerly CodeStar Connections), CodePipeline IAM role to CodeBuild, CodeBuild role access to ECR token and SSM/Secrets, EKS API mapping, node role for ECR pull, and IRSA with OIDC for pod-level AWS access.

Q34. Explain why immutable asset caching and a no-cache index strategy work together.
Scenario

Whiteboard cache model.

What the interviewer is testing

Content-addressed asset delivery.

Strong in-depth answer

Hash-based filenames guarantee content identity, immutable avoids revalidation, index.html points at the new hashes, and only the mutable index needs short caching or invalidation.

Q35. Show rollback options ranked by response speed.
Scenario

Whiteboard incident-response exercise.

What the interviewer is testing

Rollback layers and blast-radius reduction.

Strong in-depth answer

Feature flag off is fastest, followed by traffic or canary reversal, Helm rollback to a prior release, and finally a full pipeline redeploy of a previous commit.

9. Topic-First Technical Questions

Q36. Explain the difference between CSR, SSR, SSG, and ISR.
Scenario

Pure concept question.

What the interviewer is testing

Rendering architecture and route-level selection.

Strong in-depth answer

CSR renders primarily in the browser and is common for interactive authenticated apps. SSR renders per request and can improve initial HTML and SEO with greater server cost. SSG pre-renders at build time for CDN delivery. ISR serves static pages with controlled regeneration. Choose per route: marketing often SSG/ISR, authenticated shells often CSR, and dynamic SEO pages often SSR.

Q37. What is the exact difference between code splitting, tree shaking, and minification?
Scenario

Pure build-pipeline question.

What the interviewer is testing

Separating frequently confused optimizations.

Strong in-depth answer

Code splitting controls chunk boundaries and load timing. Tree shaking removes unused exports from an ES-module graph. Minification rewrites each output into a shorter equivalent. They complement one another. Measure transfer size and parse/execute cost.

Q38. Why do hashed filenames make immutable caching safe?
Scenario

Pure caching question.

What the interviewer is testing

Cache invalidation model.

Strong in-depth answer

A content hash changes when bytes change, so the URL identifies a specific version. That URL can be cached for a year with immutable because new content receives a new URL. index.html remains mutable because it points to the current hashes.

Q39. How do HTTP/2 and HTTP/3 change frontend asset-loading strategy?
Scenario

Pure networking question.

What the interviewer is testing

Protocol effects on bundling.

Strong in-depth answer

HTTP/2 multiplexes requests on one connection, while HTTP/3 uses QUIC to reduce connection setup and improve loss recovery on unstable networks. Extreme concatenation and domain sharding are less useful, but excessive chunking can still hurt scheduling, parsing, and execution. Balance granularity with runtime cost and use priority hints selectively.

Q40. Explain CSP nonce versus hash versus allowlist.
Scenario

Pure browser-security question.

What the interviewer is testing

Practical CSP design.

Strong in-depth answer

A nonce is random per response and authorizes matching inline blocks, fitting dynamic pages. A hash authorizes an exact static inline block. A source allowlist permits scripts from selected origins but does not independently control inline execution. Strong policies combine strict sources with nonces or hashes and avoid unsafe-inline and unsafe-eval.

Q41. What is same-origin policy and how is it different from CORS?
Scenario

Pure web-security question.

What the interviewer is testing

Core browser security model.

Strong in-depth answer

Same-origin policy is the browser's default restriction on cross-origin reads. CORS is a server opt-in protocol that relaxes that restriction for selected origins. CORS governs browser exposure of a response; it does not replace authentication or apply to server-to-server calls.

Q42. Why should CI use npm ci instead of npm install?
Scenario

Pure build-reproducibility question.

What the interviewer is testing

Deterministic dependency installation.

Strong in-depth answer

npm ci installs exactly from package-lock.json, removes existing node_modules, and fails when package.json and the lockfile disagree. npm install can update resolution and lock data. CI should favor repeatability and auditability.

Q43. Explain Docker image layers and why instruction order matters.
Scenario

Pure container-build question.

What the interviewer is testing

Layer cache internals.

Strong in-depth answer

Each Dockerfile instruction creates an immutable layer. Cache reuse depends on the instruction and relevant inputs. Put stable operations such as dependency installation before volatile source copy so source edits do not invalidate every expensive layer.

Q44. What does Kubernetes desired state mean in practice?
Scenario

Pure orchestration question.

What the interviewer is testing

Controller reconciliation.

Strong in-depth answer

Objects declare a target such as three replicas with image v1.2.4. Controllers compare observed state with that target and create, replace, or update resources. Operate through declarative manifests or Helm so source of truth and cluster state remain aligned.

Q45. What is the difference between Deployment, StatefulSet, and DaemonSet?
Scenario

Pure workload-controller question.

What the interviewer is testing

Controller choice.

Strong in-depth answer

Deployment manages interchangeable stateless replicas and is the usual frontend choice. StatefulSet provides stable identity, order, and persistent storage. DaemonSet ensures a pod on every selected node and is common for node agents.

Q46. Why is readiness usually more important than liveness for zero-downtime frontend releases?
Scenario

Pure release-safety question.

What the interviewer is testing

Traffic eligibility versus restart policy.

Strong in-depth answer

Readiness decides whether a new pod receives production traffic. If it succeeds before the app can serve its assets or configuration, users receive errors. Liveness only decides whether a running container should restart.

Q47. Explain HPA decision flow and common anti-patterns.
Scenario

Pure autoscaling question.

What the interviewer is testing

Metrics-based scaling mechanics.

Strong in-depth answer

HPA reads metrics, compares observed values with targets, computes replica count, and applies stabilization and scaling policies. Anti-patterns include absent resource requests, too-low minimum replicas, unsuitable lagging metrics, and startup time longer than the traffic-burst window.

Q48. What does Helm template rendering order and value precedence look like?
Scenario

Pure Helm question.

What the interviewer is testing

Operational correctness.

Strong in-depth answer

Helm starts with chart values.yaml, merges -f files from left to right, then applies --set and --set-string at highest precedence. Templates receive the merged Values plus Release and Chart context. Named templates in _helpers.tpl support reuse.

Q49. When should you use Helm rollback versus redeploying a previous commit?
Scenario

Pure incident-response question.

What the interviewer is testing

Rollback tradeoffs.

Strong in-depth answer

Use Helm rollback when the failure is deployment-level and the prior stored release is known-good. Redeploy a previous commit when chart compatibility changed, release history is unreliable, or external dependencies make the prior rendered state insufficient. Restore service first and investigate second.

Q50. Explain how CodeBuild and CodePipeline differ in responsibility.
Scenario

Pure AWS CI/CD question.

What the interviewer is testing

Workflow versus execution planes.

Strong in-depth answer

CodeBuild runs commands in isolated compute and emits logs and artifacts. CodePipeline orchestrates stages, artifacts, approvals, and integrations. Keep workflow logic visible in pipeline stages rather than burying all orchestration in build scripts.

Q51. Why should production deploy use the tested artifact instead of rebuilding?
Scenario

Pure supply-chain question.

What the interviewer is testing

Build-once, deploy-many discipline.

Strong in-depth answer

A deploy-time rebuild can drift because registries, environments, flags, or transitive dependencies change. Promoting the exact tested artifact preserves binary integrity, traceability, and reliable rollback.

Q52. Explain CloudFront cache-key design for SPAs.
Scenario

Pure CDN question.

What the interviewer is testing

Cache policy design.

Strong in-depth answer

Include only dimensions that change the response. Static assets usually require the path only; unnecessary cookies, headers, and query strings fragment cache. Separate behaviors for hashed assets, HTML shell, and dynamic API paths.

Q53. What is IRSA and why is it better than node IAM role access for pods?
Scenario

Pure cloud-security question.

What the interviewer is testing

Least-privilege workload identity.

Strong in-depth answer

IRSA maps Kubernetes service accounts to IAM roles through OIDC. Each workload receives narrowly scoped permissions and clearer audit identity. A shared node role gives pods broader common access and increases blast radius.

Q54. What are mandatory production hardening controls for a frontend container workload?
Scenario

Pure security-baseline question.

What the interviewer is testing

Layered defense maturity.

Strong in-depth answer

Run as non-root, prefer a read-only root filesystem, drop capabilities, pin digests or immutable tags, limit egress, trust only approved registries, scan images, and set requests and limits. Add TLS and WAF at ingress and CSP, secure headers, and dependency governance at the app layer.

Q55. How do you choose between S3 plus CloudFront and a containerized frontend on EKS?
Scenario

Pure platform-choice question.

What the interviewer is testing

Cost and operational reasoning.

Strong in-depth answer

Choose S3 plus CloudFront for static delivery without runtime server logic because it is simpler and cheaper. Choose EKS when runtime processing, custom middleware, cluster governance, or network controls justify the operational cost. Decide through requirements, team skills, release model, and total cost.

Scenario

Command question.

What the interviewer is testing

Preflight authorization validation.

Strong in-depth answer

Use kubectl auth can-i with the verb, resource, namespace, and impersonated identity.

kubectl auth can-i patch deployments -n production --as=system:serviceaccount:ci:deployer
Q57. What command shows the exact image digest running in production pods?

kubectl get pods -n production -l app=my-ui -o jsonpath="{range .items[*]}{.metadata.name}{' => '}{.status.containerStatuses[0].imageID}{'\n'}{end}"

Command question.

helm get manifest my-ui -n production
